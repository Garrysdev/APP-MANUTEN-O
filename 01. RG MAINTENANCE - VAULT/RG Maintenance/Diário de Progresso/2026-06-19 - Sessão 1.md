# 📝 Sessão 1 — 2026-06-19 — App RG Maintenance: build reparado

[[../00 - Projeto Overview|← Overview RG Maintenance]]

## Contexto

Pedido do Rui: "avança com a app do projeto RG Maintenance". A app (`G:\rg-maintenance\`,
Next.js 15 CMMS) estava parada na Fase 1 desde ~10/06. Ao verificar o estado, **o build estava
partido**.

## Problema encontrado

`npm run build` falhava em type-check: todas as queries Supabase tipadas devolviam `never`
(`Property 'status' does not exist on type 'never'`) e os callbacks de cookies ficavam `any`.

**Raiz:** incompatibilidade de versões. O `@supabase/ssr@0.5.2` (instalado) importa
`@supabase/supabase-js/dist/module/lib/types` — caminho que **deixou de existir** no
`@supabase/supabase-js@2.108.1`. Os `.d.ts` do ssr partem e o cliente tipado degrada por completo.
Não era bug dos nossos tipos.

## Correções (todas dentro da Fase 1 — não cruzam o Gate A1 nem tocam na decisão Firebase)

1. **`@supabase/ssr` 0.5.2 → 0.12.0** (`npm install @supabase/ssr@latest`) — alinha com o
   supabase-js 2.108. Cliente tipado volta a funcionar; aviso de Edge Runtime desapareceu.
2. **`src/types/database.ts`** — completado para conformar a `GenericSchema` do postgrest-js atual:
   - adicionados `Views/Functions/Enums/CompositeTypes` (vazios) ao schema `public`;
   - adicionado `Relationships: []` a cada tabela;
   - declarada a FK `users.company_id → companies.id` (`users_company_id_fkey`) para o embed
     `companies(name, plan)` (usado em `dashboard/layout.tsx` e `dashboard/page.tsx`) resolver.
3. **`.eslintrc.json`** criado (`next/core-web-vitals`) — `npm run lint` deixa de ser interativo.

## Resultado

- `npm run build` → ✅ verde (6 rotas geradas: `/`, `/login`, `/dashboard`, …)
- `npx tsc --noEmit` → ✅ 0 erros
- `npm run lint` → ✅ sem warnings
